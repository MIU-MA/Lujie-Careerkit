# 输出约定

## 只诊断

按以下顺序输出：

1. **诊断概览**：候选人当前定位、主要证据和最大风险，控制在一段。
2. **已有优势**：3—6 条，每条对应真实材料。
3. **问题分组**：优先处理、建议优化、可选改进；每组可按类别折叠或使用三级标题。
4. **岗位证据矩阵**：仅岗位定制模式输出。
5. **岗位调研依据**：仅使用了联网资料时输出，结论旁附链接。
6. **推荐处理范围**：列出默认建议勾选项和需要补充的事实。

不要在只诊断模式输出改写后的完整简历。

## 改写交付

至少包含：

1. **优化摘要**：实际处理了什么、没有处理什么。
2. **逐项差异**：

   ```text
   位置：
   原文：
   改写：
   理由：
   依据：
   ```

3. **待确认项**：不能安全改写的数字、职责、技能或时间。
4. **完整优化稿**：用户要求完整稿时提供。
5. **事实复核结果**：说明是否发现新增事实、强度升级或身份字段变化。

## 文件处理

- 默认保存为新文件，如 `原文件名-优化版.md`、`原文件名-岗位定制版.docx`。
- 用户要求直接编辑源文件时，先保留可恢复副本或使用版本控制。
- 无法保持 PDF/DOCX 原布局时，先交付 Markdown/纯文本改写和差异，不伪称已经保留版式。
- 结构化输出应使用通用字段，不依赖某个产品内部 JSON Schema，除非用户明确提供目标 Schema。
